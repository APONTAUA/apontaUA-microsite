## Assessment

The team recognizes that it did not fully meet the set of elements expected for the first milestone. The presentation provided context for the project, identified problems, reviewed related work, proposed a solution, and introduced goals and expected results. However, the documentation and planning did not reach the level of detail needed at this stage.

## Elements addressed, but with insufficient depth

- Project context;
- Problem identification;
- Related work analysis;
- Proposed solution;
- Project goals;
- Expected results;
- Preliminary task identification;
- Initial communication plan;
- Preliminary project calendar.

The presentation was the only artifact produced and submitted for MS1. The items above were addressed within it, but several remained preliminary.

## Elements not completed

### Planning and coordination

- Detailed task distribution;
- Formal assignment of tasks to each team member;
- Detailed semester calendar of activities and deliverables;
- Detailed communication plan.

### Analysis and specification

- Functional requirements;
- Non-functional requirements;
- State of the Art;
- Personas and identification of actors;
- Use Cases.

### Design and project materials

- System architecture;
- Domain model;
- Deployment architecture;
- Mockups;
- Project microsite.

The corresponding status pages are linked from the [MS1 overview](/apontaUA-microsite/docs/milestones/semester-1/ms1/). They explicitly record that these deliverables were not completed in this milestone.

## Team reflection

The first milestone established an initial vision for ApontaUA and helped the team understand the problem it intends to address. The team recognizes, however, that the submission focused too heavily on a conceptual presentation of the solution and was not accompanied by several planning, analysis and specification artifacts expected at this stage.

The absence of these elements made it harder to define the work in detail, distribute responsibilities and prepare the next stages in a structured way.

This assessment is a starting point for improving the project's organization, planning and follow-up in subsequent milestones. It records the gaps directly rather than treating them as completed work.
