## Assumptions and limits stated in the source

- Initial reference scenario: approximately **300 registered DETI users**. This is not a concurrent-user count.
- The team must define concurrent users and expected document volume before load testing.
- A formal uptime percentage is not fixed. NFR-50 asks for a documented objective and measurement approach before pilot use.
- NFR-10 explicitly imposes no strict two-second response-time target at this stage; response times must be measured under a documented load scenario.
- Accessibility, including WCAG 2.2 AA where applicable, must be validated; it is not reported as tested.

## Proposed validation and test plan

The source proposes load testing with a DETI-like dataset and a documented registered-user and concurrent-user scenario; measurement of search, metadata, upload and processing times; recovery tests that verify the original file remains intact; server-side authorization and file-validation tests; representative OCR and similarity evaluation (including false positives and false negatives); and an availability target after hosting and monitoring are selected.

## Open decisions in the source

Choose a measurable availability target and measurement window; define concurrency and pilot document volume; set performance objectives from early measurements; select and test supported browsers; agree retention/deletion periods; and define how accessibility checks will be validated. These remain unresolved in this working draft.
